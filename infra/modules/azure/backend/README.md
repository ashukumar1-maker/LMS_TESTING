# Azure Backend Module

Creates Azure resources that support backend runtime and backend image delivery.
This roughly corresponds to the GCP backend module boundary.

## Responsibilities

- Creates Azure Container Registry for backend images.
- Runs a one-time Azure Container Registry Tasks bootstrap build that pushes the
  default `:init` backend image.
- Creates Azure Key Vault for backend runtime secrets.
- Disables public Key Vault network access and exposes the vault through a
  Private Endpoint.
- Creates the Key Vault private DNS zone and VNet link.
- Uses `../secret` to write the computed `DATABASE_URL`, generated database
  password, user-provided backend secrets, and placeholder Sentry auth token
  into Key Vault through ARM secret resources.
- Creates Azure Workload Identity identities for the backend service account and
  External Secrets service account.
- Grants the backend identity blob data access to the storage account.
- Grants the External Secrets identity read access to Key Vault secrets.
- Builds the backend runtime environment variable map exposed by deployment
  outputs.

## Key Inputs

- `acr_name`, `key_vault_name`: Globally constrained Azure resource names chosen
  by the deployment module.
- `tenant_id`, `current_object_id`: Used for Key Vault RBAC and initial secret
  creation.
- `virtual_network_id`, `private_endpoint_subnet_id`: Used for Key Vault
  Private Endpoint and private DNS integration.
- `oidc_issuer_url`: AKS issuer used for federated identity credentials.
- `backend_namespace`, `backend_service_account_name`: Kubernetes subject for
  backend workload identity.
- `external_secrets_namespace`, `external_secrets_service_account_name`:
  Kubernetes subject for External Secrets workload identity.
- `storage_account_id`, `storage_account_name`, `backend_container_name`: Blob
  storage access and runtime env wiring.
- `database_url`: Computed by `../database` and stored as a Key Vault secret.
- `database_password`: Generated by `../database` and stored as a Key Vault
  secret for operator recovery/rotation workflows.
- `backend_env_vars`, `backend_secret_env_vars`: User-provided backend config.

## Bootstrap Image Push

Terraform runs `az acr run` through `null_resource.build_and_push_initial_image`
to seed ACR with the default `backend:init` image used before the first
successful backend deployment build. The command stages a minimal upload context
containing the repo `backend/` directory contents and `acr-build-initial.yaml`,
so the backend `.dockerignore` filters the upload before Azure receives it. The
task runs an Azure Container Registry Tasks build with `DOCKER_BUILDKIT=1`, then
pushes both `backend:init` and `backend:latest`.

This path is a bootstrap compatibility path, not the steady-state deployment
runner. Normal CD can later replace the bootstrap image with commit-specific
backend build artifacts.

The bootstrap build uses Azure AD auth from the authenticated `az` CLI identity
running Terraform. ACR admin credentials remain disabled. The caller needs
permission to queue ACR Tasks quick builds and push to the registry, such as
Owner, Contributor, or least-privilege registry-scoped `Container Registry Tasks
Contributor` plus `AcrPush` for non-ABAC registries. For the default non-ABAC
registry, the task pushes through the registry context and does not require
exposing registry admin credentials.

## Outputs

- `artifact_registry_repository_id`: ACR resource ID.
- `container_registry_login_server`: Registry host used in image names.
- `backend_runtime_env_vars`: Non-secret runtime environment variables.
- `backend_secret_refs`: Key Vault secret names keyed by backend env var name.
- `default_container_image_uri`: Initial backend image URI.
- `key_vault_id`, `key_vault_name`: Key Vault details for downstream modules and
  setup instructions.
- `sentry_auth_token_secret_id`, `sentry_auth_token_secret_name`: Secret scope
  and name used by frontend source map upload workflows.
- `database_password_secret_name`: Key Vault secret name containing the
  generated PostgreSQL password.
- `backend_identity_client_id`, `external_secrets_identity_client_id`: Values
  needed by Kubernetes service account annotations.

## Notes

The runtime env map exposes Azure Blob storage through
`AZURE_STORAGE_ACCOUNT_NAME` and `AZURE_STORAGE_CONTAINER_NAME`. The legacy
`MOUNTED_BACKEND_GCS_BUCKET_NAME` GCP setting is intentionally omitted for Azure
because backend startup no longer requires it.

Key Vault is private-only. Secret writes are delegated to `../secret`, which uses
the Azure management-plane `Microsoft.KeyVault/vaults/secrets` child resource so
bootstrap applies do not need public vault data-plane access. Runtime reads and
manual secret operations still need VNet connectivity to the private endpoint.
